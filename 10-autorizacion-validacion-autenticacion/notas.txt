    - Creacion de usuarios

La idea es que el usuario se pueda registrar por medio de su correo electronico
Tambien veremos como crearnos un error personalizado con diferentes tipos de constructores

Ademas veremos otra forma de trabajar usando solamente Inyeccion de dependencias para evitar usar el patron repositorio
El proyecto por defecto se nos dio iniciado 
    - Tenemos en la carpeta "config" tenemos la configuracion de las variables de entorno
    - En la "presentation" tenemos la definicio de las rutas y el servidor
    - El archivo app con la funcion asyncrona autoinvocada donde se manda a llamar el servidor
    - El archivo de docker con dos BD para eligir si queremos usar PostgreSQL o Mongo
Reconstruimos los modulos de Node:
    - npm i

En esta ocasion decidimos trabajar con MongoDB
    - En el archivo de docker ya estan asignado el nombre de usuario y password para no sobrecargar la variable de entorno

Levantamos la Base de datos
    - docker compose up -d
Arrancar la aplicacion  
    - npm run dev

Queremos mantener una total separacio de lo que viene en la BD con el como va fluir los datos de la aplicacion
porque si la BD cambia, la aplicacion no deberia verse afectada y solo hacer los cambios en la carpeta "data" donde esta la estructura de la BD

Si nos vamos al controlador en el register para crear un usuario hay que pensar cual informacion es la que requerimos que nos manden en el body
(estas serian cada una de las propiedades obligatorias que definimos en la entidad de usuario), y ademas esta informacion tenemos que validarla y verificarla
para que sean del tipo de dato que esperamos y para esto es el DTO (Los Dtos los vamos a crear por cada endpoint que vayamos a recibir informacion)
cuando recibimos un objeto de tipo DTO ya sabemos la informacion que tiene y que esta validada.

En el controlador no deberiamos de hacer el trabajo de la creacion, validacion y todo el proceso del DTO, el controlador es solo la ruta del endpoint
lo que vamos a implementar para esto es un servicio que es como un gestor de estado

Para encriptar las contraseñas instalamos el paquete
    - https://www.npmjs.com/package/bcryptjs
tambien usaremos el patron adaptador para que podamos cambiar de paquete facilmente
para que nuestro proyecto no dependa de entidades externas, por ejemplo en este caso tenemos una dependencia del modelo que cuando nos tocara cambiar de BD
vamos a tener que modificar todos los Servicios (pero estos serian los unicos afectados con esta logica)
Pero si queremos ser mejores, en el AutServices podemos inyectar el repositorio para que podamos cambiar facilmente de BD

JWT
    Si queremos mantener la sesion del usuario lo vamos a hacer mediante un JWT, este es un String muy grande que esta separado en 3 partes
        - Header: Aqui esta el algoritmo que fue utilizado para la encriptacion del token
        - Payload: Aqui esta la informacion que requerimos guardar para identificar al usuario
        - Firma Autorizada: Esta la usa el backen para garantizar que el payload y la firma coinciden, la firma tiene una llave secreta con la que se genero el token

    Nosotros usaremos para que cuando alguien se autentique en la aplicacion le regresemos el token y ademas lo usaremos para validar las rutas porque habran rutas que solo
    siertos usuarios podran entrar o con cierto Rol

    Vamos a usar un paquete para generar los JWT
        - https://www.npmjs.com/package/jsonwebtoken

Enviar correos electronicos
     Cada vez que alguien se registra, a este usuario le llegara un correo que al hacer click en el enlace lo va a mandar al servidor y vamos a validar
     al usuario sabiendo cual correo es el que a sido validado, para lograr esto vamos a mandar un token al correo electronico con una fecha de expiracion
     ese token caeria en el Endpoint, el endpoint lo va a leer y hara el proceso respectivo para validar el correo electronico

     Aqui tambien vamos a usar Ngrock donde podemos crear un tunel en el localhost donde esta la aplicacion exponiendo el puerto
     para que pueda ser usado desde internet para poder hacer la prueba desde el telefono y fingir como si estubieramos la aplicacion subida 
     ya a produccion a alguna nube.

     El objetivo va a ser que el mecanismo de envio de correos electronicos solo se va a disparar cuando se crean nuevos usuario, es decir cuando pase por el registro
     solo ahi se activara el envio del mensaje 
        - Asi que para probar el funcionamiento debemos de registrar un usuario con el Endpoint de registro en Postman con un correo real

    Con ngrock vamos a exponer un puerto de nuestra computadora para asi poner en produccion y a internet con un solo comando el puerto donde se esta mostrando la aplicacion
    y acceder como si fuera una pagina, asi podremos hacer pruebas como si estubieramos en produccion la aplicacion, esto tambien sirve para cuando queremos pasarle a algun cliente
